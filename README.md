# Colophon MCP

## Prologue

A book could pass through several hands before it was finished. The text was copied, the rubrics and the pictures were set in, and the copy was often corrected, sometimes against another — by the scribe who made it, or by an older monk.

The [emulator](https://github.com/tulinmola/colophon-emulator) runs the machines of the 8-bit era from the inside, the [player](https://github.com/tulinmola/colophon-player) is where a person watches one run, and the [archive](https://github.com/tulinmola/colophon-archive) is where what was found is written down. This is where another reader is let in: an agent, which has no eyes on the glass and no fingers on the keys, and so asks the machine for all of it — to run, to stop, to type, to show its picture and what it holds. It asks through the [Model Context Protocol](https://modelcontextprotocol.io), and it may stand up as many machines at once as its question needs, so that a game's releases for two machines can be read side by side.

What it finds is not the record. A finding is to reach the archive as something the machine can be asked again — the copy it was read from, named by its hash, the build it ran on, and what was done to it and at which tick — and since nothing in the machine consults a clock, the same questions will get the same answers for whoever asks them next.

The protocol will change and the machines will not. That is why it is spoken here and not in the emulator.

## Building

Building it takes Rust through rustup, which fetches the toolchain `rust-toolchain.toml` pins on first use, a C compiler, libclang for bindgen to read the emulator's headers with, and a checkout of [the emulator](https://github.com/tulinmola/colophon-emulator) standing beside this one; `EMULATOR_DIR` names another.

```sh
make                  # build
make test             # the tests
make check            # formatting, linting and the tests
make test-sanitized   # the tests under AddressSanitizer and UBSan
make test-firmware    # the firmware, against the emulator's command line
make test-disassembly # the disassembler, against two disassemblies made elsewhere
make test-inspector   # the server against the protocol's own Inspector
```

`make check` also wants clang-format and clang-tidy. The check workflow pins the release it runs, because another may format differently or find other things. `make test-sanitized` wants a C compiler with AddressSanitizer and UBSan. `make test-firmware` has the emulator fetch its firmware, by the hashes it pins, and build its command line. `make test-disassembly` has the emulator fetch its firmware too, and fetches SkoolKit and The Complete Spectrum ROM Disassembly by the hashes the Makefile pins, which wants curl, tar, sha256sum or shasum, and Python 3. `make test-inspector` fetches the Inspector through npx, which wants Node 22.19 or later.

## Where it stands

An agent can run the machines, stop them and watch them, read them and see them, type at them, give them their discs and tapes, save them, keep them as they stand and put them back there, and read what has been done to them. The server answers it over standard input and output, in the protocol's revisions 2026-07-28, 2025-11-25 and 2025-06-18, and names the build in its answers about itself and its tools. It stands up the machines the emulator's command line names, from power-on or from a snapshot, and names every file it built one from by its hash; it runs them by the frame or the tick and steps them by the instruction, saying how far each request took them, stops them where it is told, gathers what they do on the way, the first of it or the last, and counts it, by address or by the instruction that did it, into its answer or, for a stretch too long for one, into a file named by its hash, and calls their routines; it reads and writes whatever they hold by its path, refusing what the emulator could not run from, and reads and writes their memory as their processors would. It shows their monitors' pictures as the emulator's command line draws them, reads a CPC's memory as a picture, as its video hardware reads it, flat or in columns, in any mode and palette, and reads memory back as instructions. It types at them as the command line types, holds their keys down through a run, gives a CPC its discs and a Spectrum its tapes, each copied into the machine and named by its hash, and saves them as the command line saves them, to files it writes only where none is. It keeps a machine exactly as it stands, discs, tape and all, and puts it back there, each state a branch to come back to, and keeps a journal of every request that stood a machine up or changed it, on the branch it stands on, with its tick, from which the machine is made again. [The server](docs/index.en.md) is the full account. The tools to come are to be learned from the colophons that ask for them.
